# QuantumOrbital

QuantumOrbital is a modular scientific visualization of the hydrogen ground state. It connects an analytic hydrogen 1s model to a sampled 3D probability cloud, a radial probability graph, and an enclosed probability calculator.

## Physics model

For hydrogen, the stationary wavefunction separates into radial and angular parts, `ψₙₗₘ(r,θ,φ) = Rₙₗ(r)Yₗₘ(θ,φ)`. The initial implementation supports only `n=1, l=0, m=0`:

```text
R₁₀(r) = 2 a₀^(-3/2) exp(-r/a₀)
Y₀₀    = 1 / √(4π)
ψ₁₀₀   = 1 / √(πa₀³) exp(-r/a₀)
|ψ₁₀₀|² = 1 / (πa₀³) exp(-2r/a₀)
```

The Bohr radius `a₀ = 5.29177210903×10⁻¹¹ m` is held in SI units in the physics modules. The 3D display uses `a₀` as one scene unit. The radial probability per unit radius is `4πr²|ψ|²`, equivalently `r²|R₁₀|²`. Its cumulative probability through radius `R` is `1 − exp(-2R/a₀)(1 + 2R/a₀ + 2R²/a₀²)`.

The point cloud represents probability density. It is **not a literal physical cloud surrounding the nucleus**, and it does not show a classical path or a definite electron position. Samples are generated by inverse-CDF sampling of the normalized 1s radial distribution, with uniform directions on the sphere.

## Stack and architecture

- React and Vite for the application
- Three.js, React Three Fiber and Drei for the interactive scene
- Recharts for the radial distribution plot
- Vitest for the independently testable physics layer

Physics lives in `src/physics`, point generation and Three.js components in `src/visualization` and `src/components`, shared React state in `src/hooks`, and presentation in `src/styles`. Physical quantities stay in SI; the scene and graph use explicit Bohr-radius units.

## Install and run

```sh
npm install
npm run dev
```

Create a production build with `npm run build`. Run the physics tests with `npm test`.

## Adding an orbital

Add a normalized radial solution in `src/physics/hydrogen/radial.js`, the relevant normalized spherical harmonic in `sphericalHarmonics.js`, and connect them through an orbital wavefunction and density implementation. Add its `(n,l,m)` tuple to `ORBITALS` only after the functions are implemented. Extend probability integration and sampling for that orbital, then expose the implemented state through `useQuantumState`; controls should continue to use `isValidQuantumNumbers` to enforce `n≥1`, `0≤l<n`, and `|m|≤l`. Add normalization, density, radial distribution, and region-probability tests for each new state.

## Current scope

Only hydrogen 1s is implemented. The cloud sampler is deterministic and truncates the display at 12 Bohr radii, omitting a negligible tail (about `1.2×10⁻⁸` probability) while keeping the displayed sample count useful. Later orbitals need their own radial and angular functions and an appropriate sampler; this release intentionally has no placeholder orbitals.
